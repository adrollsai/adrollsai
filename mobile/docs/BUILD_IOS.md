# iOS build guide

## Status: configured, not compiled

The machine this was developed on runs Windows. There is no macOS, no Xcode and
no iOS Simulator, so **the iOS target was authored but never built or run.**

Everything that can be authored without a Mac has been:

| Item | State |
|---|---|
| Bundle identifier | `com.nobogent.app` — matches the shipping Capacitor shell so this can ship as an update (set in `project.pbxproj` for all 6 build configurations) |
| Display name | `Nobogent` (`CFBundleDisplayName`, `CFBundleName`) |
| App icon | Full `AppIcon.appiconset`, all 15 sizes, generated by `tools/generate_icons.ps1` |
| Launch screen | `LaunchScreen.storyboard` (Flutter default, light system background) |
| URL scheme | `nobogent://auth-callback` registered in `CFBundleURLTypes` |
| Orientations | Portrait + both landscapes on iPhone; all four on iPad |
| Export compliance | `ITSAppUsesNonExemptEncryption = false` — no custom cryptography |
| Privacy usage strings | Written but **commented out** — see below |
| Deployment target | Flutter's default (iOS 13+); verify against your App Store requirement |

### Why the permission strings are commented out

App Review rejects apps that declare usage descriptions for APIs they never call,
and an unnecessary prompt is a bad experience. The app currently requests **no**
runtime permission — media is streamed over HTTPS, not captured, and attachments
are not implemented (see `LIMITATIONS.md`).

`Info.plist` therefore contains ready-to-use, written-for-humans strings for
camera, photo library and microphone, commented out. When a feature ships,
uncomment the matching key **and** add an in-app rationale at the same time:

```xml
<key>NSMicrophoneUsageDescription</key>
<string>Nobogent uses the microphone to record a voice brief for the AI agent.</string>
```

## What must be done on a Mac

### 1. Build and run

```bash
flutter pub get
cd ios && pod install && cd ..          # first run, and after adding plugins
open -a Simulator                        # boot a simulator
flutter run                              # debug on the simulator
```

### 2. Verify the things a non-Mac cannot

- [ ] Interactive back-swipe from the left edge on every pushed screen
- [ ] Safe-area insets on notched hardware (the tab bar must sit above the home
      indicator, content must not clip under it)
- [ ] Keyboard avoidance in the session composer and the sign-in form
- [ ] Dynamic Type at the largest accessibility sizes (the app clamps to 1.5×;
      confirm that clamp feels right on device)
- [ ] Haptics on approve/decline and on opening a task
- [ ] Pull-to-refresh rubber-banding (uses `CupertinoSliverRefreshControl`)
- [ ] Video playback with `AVPlayer` on a real generated MP4
- [ ] Dark mode following the system, and the app's own Light/Dark override
- [ ] VoiceOver labels and reading order on Home, Inbox and CRM

### 3. Signing

1. Apple Developer account, then create the App ID `com.nobogent.app`.
   **This identifier already exists on the App Store if the Capacitor shell was
   ever released** — confirm, because an App Store Connect record is permanent.
2. `open ios/Runner.xcworkspace`
3. Signing & Capabilities → select your team → let Xcode manage the provisioning
   profile. Do not commit certificates or profiles.
4. If the existing app is already on the store, this build needs to be uploaded
   under the **same** App Store Connect app, with a build number above the last
   Capacitor build.

### 4. Release

```bash
flutter build ipa --release \
  --dart-define-from-file=dart_defines.json \
  --export-options-plist=ios/ExportOptions.plist
```

`ExportOptions.plist` is gitignored — generate one in Xcode (Product → Archive →
Distribute App) or write it by hand with your team ID.

Upload with Transporter or `xcrun altool`, then complete in App Store Connect:

- [ ] Screenshots at 6.9", 6.5" and 5.5" (the simulator can produce these)
- [ ] Privacy nutrition label — the app stores an auth token in the Keychain and
      task transcripts on-device; it does not sell data
- [ ] Age rating
- [ ] Privacy policy URL (`https://nobogent.com/privacy-policy`)
- [ ] App Review notes: if you submit while the AI agent is super-admin-only,
      mention that the agent is gated server-side

### 5. Supabase redirect allow-list

OAuth and password-recovery round-trips need `nobogent://auth-callback` added to
**Supabase → Authentication → URL Configuration → Redirect URLs**. This is a
dashboard setting, not repo configuration, and it is required on iOS *and*
Android before either can complete an OAuth flow.

## How the iOS interface was verified without a Mac

`lib/core/platform/nobo_platform.dart` resolves the platform from
`defaultTargetPlatform`. A debug-only dart-define overrides it:

```bash
flutter run --dart-define=NOBO_FORCE_IOS=true
```

That runs the **real Cupertino widget tree** — `CupertinoTabBar`,
`CupertinoSlidingSegmentedControl`, Cupertino page transitions, iOS touch
feedback — on the Android emulator, where it can be screenshotted.
See `docs/screenshots/ios-*.png`.

**What this proves:** layout, typography, spacing, overflow behaviour and the
correct platform branch for every adaptive component, at real phone dimensions.

**What it does not prove:** native behaviour — back-swipe feel, safe areas on
notched hardware, keyboard animation, haptics, `AVPlayer`, VoiceOver. Those need
an actual iPhone and are listed in step 2 above.
